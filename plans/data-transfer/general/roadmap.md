# Импорт и экспорт данных

Автор: Claude Code, claude-sonnet-5-5, 2026-10-21

## Зачем

Пользователь ведёт историю с 2020 года в Android-приложении Time Tracker (Zafer Ertas, `zzz1zzz.tracktime`) и хочет перенести её во Freem. Кроме импорта нужен экспорт данных Freem, а набор
форматов должен расширяться: добавление нового формата не должно трогать ядро. Во Freem сегодня нет ни импорта, ни экспорта, ни абстракции «формат»; нет файлового хранилища и фоновых задач.

Образец выгрузки Time Tracker (обезличенный) лежит в `plans/data-transfer/samples/All_21 Oct Wed.csv`. Факты о формате (проверено разбором образца):

- CSV, UTF-8 без BOM, строки с LF, **без кавычек**. Колонки: `ID`, `Time item ID`, `Start Date`, `Start Time`, `End Date`, `End Time`, `Duration`, `Duration in milliseconds`, `Activity ID`,
  `Activity Name`, `Notes`, `Category ID`, `Category Name`. В заголовках и ячейках пробелы после запятых; пустая заметка приходит как один пробел.
- Дата `d MMM yyyy` с английскими месяцами, время `HH:mm` без секунд и без часового пояса. Расхождение между минутными началом и концом и точной длительностью до 55 секунд на запись.
- Запятая в заметке ломает разбор строки (кавычек нет): надёжный приём — 10 полей слева и 2 справа, всё между ними — заметка. Перевод строки внутри заметки в образце не встречается.
- В образце нет пересечений, записей через полночь, записей без конца; колонки категории пустые.

За образец архитектуры взят механизм импорта выписок в соседнем проекте StashIt (`docs/statement-parse-convert-rule-engine.md` там): загрузка файла, разбор парсером конкретного формата из DI-реестра в
сохранённые сырые строки, затем преобразование строк в итоговые сущности. Из него переносятся поэтапный конвейер с сохранением промежуточного состояния, реестр форматов с тестом на полноту и статусы
сущности импорта с атомарными переходами. Не переносятся RuleEngine, S3 с job'ами и открытые key-value поля строки: целевая модель Freem маленькая и фиксированная.

Решения пользователя (2026-10-21):

- Поэтапный подход с сохранением строк импорта в БД. RuleEngine не нужен; вместо него таблица соответствия «активность источника → активность Freem (существующая или создать новую)».
- Заметки источника (`Notes`) пишутся в название записи (`Name`). Категории источника отбрасываются. Цвет активности в источнике отсутствует, при создании активности он выбирается детерминированно.
- Время записи берётся из файла как есть: начало и конец с минутной точностью, длительность из файла игнорируется.
- Часовой пояс файла задаётся пользователем при импорте; если не указан, берётся `TimeZoneOffset` из его настроек.
- Экспорт делается сразу, в первой итерации, в нативном формате JSON Freem. Импорт нативного JSON тоже входит в план (добавлено 2026-10-21): он проходит тем же конвейером, что и импорт Time Tracker,
  и даёт проверку цепочки туда и обратно. Записи без конца считаем невозможными, `RunningRecord` для этого импорта не нужен.
- После разбора фронтенд показывает список строк, пользователь выбирает строки для преобразования в записи, одиночно или несколько сразу; применяются только выбранные. История большая (с 2020 года),
  объём заранее не известен, поэтому список строк должен быть постраничным, а выбор должен работать и на всех строках сразу, а не только на загруженной странице.

Предварительные соображения (уточняются в исследованиях этапов):

- Нативный JSON богаче Time Tracker: у него есть теги, описание записи, несколько периодов с собственными описаниями и смещениями, цвет и статус активностей. Поэтому строка импорта не может быть
  плоской «одна запись — один период», а соответствие при применении охватывает не только активности, но и теги. Часовой пояс, указанный при импорте, нужен только форматам, в которых времени
  без пояса (Time Tracker); для JSON берутся смещения из файла.

- Разбор файла синхронный, в запросе загрузки; сам файл не хранится, хранятся только разобранные строки. Фоновые задачи вводятся, только если синхронного разбора окажется недостаточно.
- Записи создаются через существующие механизмы домена (события, инварианты). Как не завалить хранилище и поток событий тысячами записей (порции, одно сводное событие) решается на этапе применения.
- Дубли и фильтрация (решение пользователя 2026-10-23): строки импорта неизменяемы и статусов не имеют, дубли не отслеживаются и остаются на совести пользователя, список показывает все строки. Дедупликация
  (в том числе ссылка записи на строку импорта, правки `Record`, вывод «уже импортировано» из записей) и фильтры откладываются на потом.

## Этапы

1. **Абстракции форматов и экспорт в JSON.** Нейтральная модель обмена данными, интерфейсы формата импорта и экспорта, DI-реестр форматов с тестом на полноту, схема нативного JSON Freem с версией
   (рассчитанная на чтение и запись), use case и эндпоинты экспорта и списка форматов. → фактура в `plans/data-transfer/stages/01-formats-export.md`.
2. **Модель импорта и хранилище.** Сущность импорта (пользователь, формат, имя файла, статус, соответствие активностей и тегов) и строки импорта (типизированные, с несколькими периодами, тегами и описанием, неизменяемые),
   таблицы и миграция, репозитории, атомарные переходы статуса, события. → фактура в `plans/data-transfer/stages/02-import-storage.md`.
3. **Загрузка и разбор.** Use case и эндпоинт загрузки файла с выбором формата и часового пояса, парсеры выгрузки Time Tracker и нативного JSON по реестру из этапа 1, сохранение строк, предупреждения и ошибки разбора,
   постраничный список строк и найденных активностей. → фактура в `plans/data-transfer/stages/03-parse.md`.
4. **Применение выбранных строк.** Правка соответствия активностей, преобразование выбранных строк (одиночных, множества, всех) в записи, создание новых активностей и тегов, порционная запись, решение по событиям. → фактура в `plans/data-transfer/stages/04-apply.md`.
5. **Фронтенд.** Загрузка файла, выбор формата и часового пояса, список строк с одиночным и множественным выбором, постраничность на большом объёме, сопоставление активностей, применение и результат,
   скачивание экспорта. → фактура в `plans/data-transfer/stages/05-frontend.md`.
