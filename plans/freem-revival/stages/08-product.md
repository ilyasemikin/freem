фич: каждая берётся отдельно, со своим согласованием направления.

## Зафиксированные факты

Проверено чтением кода (`_Src/Freem`, `Freem.Web`), состояние на коммит `e02ac8b`.

- **Что есть в API** (`Freem.Web.Api.Public/Controllers/V1`): активности (CRUD, поиск по имени, архивация и
  разархивация), теги (CRUD, поиск по имени), записи (CRUD, список, список за период), текущая (running) запись
  (старт, стоп, обновление, удаление, получение), статистика (`per-period`, `per-days`), события (`events`, список),
  пользователь (`me`, `register`, настройки `DayUtcOffset`), авторизация (`auth/*`, прокси к EgoHub).
- **Что из этого фронтенд не использует:** архивация/разархивация активностей (в UI нет), настройки пользователя
  (`DayUtcOffset` нигде не редактируется, хотя от него зависит статистика), статистика по дням (`perDays`
  есть в кэше сущностей, на страницах не используется), события (`events`) — клиента нет.
- **Что есть в UI** (маршруты): `/` (вкладки Tags / Records / Statistics), `/activities`, `/records`,
  `/records/statistics`, `/tags`; запись можно добавить вручную, отредактировать, удалить; running-запись
  запускается и останавливается на странице активностей; статистика — круговая диаграмма и список по активностям за
  выбранный период (день/месяц/год).
- **Статистика в домене** (`Freem.Entities/Statistics/Time`): `TimeStatistics` с периодом, суммарным
  записанным временем и временем по активностям — другой аналитики (тренды, сравнение периодов, по тегам, цели)
  нет.
- **Telegram:** `UserTelegramIntegration` (только `Id`) есть в домене, хранилище и событии
  `TelegramIntegrationChanged`, но use case'ов и эндпоинтов для него нет — заготовка без функциональности.
- **События:** журнал событий пишется в БД, публикация наружу — `NullEventPublisher` (Kafka удалена на этапе 3);
  потребителей, которые что-то делают по событиям, нет.
