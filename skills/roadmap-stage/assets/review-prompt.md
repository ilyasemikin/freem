# Шаблон промпта для независимого ревьюера этапа

Подставь `<N>`, `<название этапа>`, `<slug>` инициативы и путь к stage-файлу. Агент: `general-purpose`.

---

Независимое ревью этапа <N> («<название этапа>») roadmap `plans/<slug>/` в репозитории
<корень репозитория>. НИЧЕГО не коммить и не правь файлы: только читай и отчитывайся. Не запускай
docker и не трогай инфраструктуру; сборку/тесты запускай только те, что нужны для критерия
готовности этапа.

Изменения не закоммичены: смотри `git status` и `git diff`, плюс новые untracked файлы (stage-файл
`plans/<slug>/stages/NN-*.md`).

Прочитай `skills/roadmap/SKILL.md` и `skills/roadmap-stage/SKILL.md` (читай напрямую, через Skill
tool они недоступны) и проверь:

1. Код: корректность правки, соответствие стилю соседнего кода, затронутые потребители, не
   сломан ли кто-то из них. Запусти проверки из критерия готовности (например `npx tsc --noEmit`,
   `npx eslint <файлы>`). Глубокий разбор корректности не дублирует `code-review`.
2. Критерий готовности из stage-файла: выполнен ли он изменениями и записанными проверками.
3. Правила roadmap/roadmap-stage: авторство и формат записей в "Статус и изменения" (дата,
   агент, ID модели), текст "Зачем"/"Этапы" roadmap не правился по инициативе агента, в stage-файле
   нет лишнего пошагового плана и непроверенных фактов, язык русский, честность про то, что
   проверено, а что нет.
4. Закрытие: предыдущий этап отмечен закрытым пользователем (запись с коммитом в roadmap и в его
   stage-файле). Текущий этап пользователем ещё НЕ закрыт: записи "закрыт" быть не должно.

Итог: вердикт APPROVE / APPROVE WITH NOTES / REQUEST CHANGES, список замечаний с file:line и
пометкой, блокирующее оно или нет. Коротко, на русском.
